# deployments/

The contract matrix the generator reads and writes, and deployment records. A local-chain run (`scripts/deploy-and-publish.ts`, `scripts/publish-pointer.ts`) writes its record to
`MN_DEPLOYMENT_FILE` — by convention `out/local-deployment.json` — which is not committed: addresses,
deploy and call transactions, and every pointer publication (segment, parts, intent hash, transaction, block).

| File | What | Written by |
|---|---|---|
| `reference-set.json` | The token reference set every 00024 contract set is generated from (spec 00020 §7.1 / 00024 §6): one row per token, its ordered deployment steps. **A pinned copy, unmodified**, of [`acedward/mip-0018-midnight-contracts`](https://github.com/acedward/mip-0018-midnight-contracts) `deployments/reference-set.json` at `cb6c675ddbbb4a82d0bcaf87ad863c934becce31` (branch `feat/00024-01-mip-0018`; git blob `0cc572fb247bbf2ed04703be046ca78cded6bd3a`; SHA-256 `6b37b56af510d3483899e04690762b12dc0a059853ed07fdd4036e5c2bf6a40b`, pinned by `test/sources.test.ts`). Do not edit it here. | copied |
| `public-interface-set.json` | The PI rows of spec 00024 §6.B: which reference rows become `LSUNPI`, `SSTARPI`, `CNSTPI`, `UPROMPI`, the base each is built on (OpenZeppelin module or the own unshielded template), the interface form (FULL) and the path of its bundle on the local stack's static server. | by hand (the set's definition) |
| `dual-set.json` | The DU (dual) rows of spec 00024 §6.B: which reference rows become `SNEBDU`, `LMOONDU`, `UMETDU`, `DAURDU`, the MIP-18 twin whose metadata each carries step for step, the base (OpenZeppelin module or the own unshielded template), the interface form (HIDDEN) and the path of its bundle on the local stack's static server. | by hand (the set's definition) |
| `dual-matrix.json` | The ordered plan for each DU contract, in the same step shape as `generated-matrix.json`: every MIP-0018 declaration of the twin (one circuit call, one intent, one package of `parts` events; the exact `payloadHex`), the mints, and the final `publishBundle` step. | `scripts/generate-du-contracts.ts` |
| `generated-matrix.json` | The ordered plan for each PI contract: constructor arguments after the emitter-secret hash, each step's circuit, the exact 256-byte package of every `repository` declaration, and the final `publishBundle` step with its URL and part count. | `scripts/generate-pi-contracts.ts` |
| `bundles.json` | The public-interface pointer of each PI contract (`form` FULL) and each DU contract (`form` HIDDEN) as `public-interface-deploy-check` computed it from `bundles/<path>/`: URL, commitment, `payloadHex` (commitment ++ URL, zero padded to 256·parts) and `partsHex` (the `publishBundle` arguments, in order, one guaranteed intent), the published circuits and the verify-only ones. | `scripts/bundle.ts` |
